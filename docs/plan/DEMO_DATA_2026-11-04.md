## 3. Danh sách lỗi app gặp phải và cách xử lý / vượt qua

1. **Supabase Session Pooler Exhaustion (`EMAXCONNSESSION: max clients reached in session mode - pool_size: 15`):**
   - *Nguyên nhân:* DB kết nối qua Supabase session pooler port 5432 bị giới hạn cứng 15 connection. Khi web dev server, worker và các câu lệnh `Promise.all` cùng lúc bắn 10+ query, pooler bị nghẽn connection.
   - *Cách xử lý:* Chuyển các câu lệnh đếm kiểm tra từ `Promise.all` sang chạy tuần tự (sequential `await`), đồng thời cấu hình worker indexer batch `INDEXER_RANGE_SIZE=5` để tránh interactive transaction timeout (P2028).
2. **ThirdwebAuth SIWE Domain 401 Mismatch:**
   - *Nguyên nhân:* Auth cookie kiểm tra domain khớp `NEXT_PUBLIC_APP_URL`. Ban đầu web server chạy trên port 4001 nhưng config trỏ 4000.
   - *Cách xử lý:* Khởi động web dev server với `PORT=4001 NEXT_PUBLIC_APP_URL=http://localhost:4001 bun run dev`.
3. **Thiếu tiêu chí kiểm thử (`NO_APPROVED_CRITERIA` khi gọi `selectDeveloper`):**
   - *Nguyên nhân:* Logic backend yêu cầu mỗi bài toán phải có ít nhất 1 test case được phê duyệt (`isApproved: true`) trước khi được phép chọn ứng viên và tạo reservation.
   - *Cách xử lý:* Tự động tạo test case (`createTestCase`) và duyệt tiêu chí (`updateTestCase`) trước khi gọi `selectDeveloper`.
4. **Zod format & Event Socket Chat Wave 6:**
   - *Nguyên nhân:* `handlers.ts` bắt buộc `task:join` nhận trực tiếp `issueId: string` (thay vì `{ taskId }`) và `message:send` yêu cầu schema `{ issueId, content, type: "TEXT" }`.
   - *Cách xử lý:* Cập nhật hàm gọi Socket trong `scripts/demo/populate.ts` để truyền đúng định dạng Zod schema và join phòng bằng role client/developer tương ứng.
5. **Yêu cầu giao hàng on-chain trước khi Release (`prepareReleaseFunds` trả về `NO_DELIVERY`):**
   - *Nguyên nhân:* Hợp đồng và backend yêu cầu `projection.deliveryHash` phải tồn tại trên chain trước khi khách hàng có thể release funds hoặc yêu cầu sửa đổi bài nộp.
   - *Cách xử lý:* Bổ sung bước `prepareSubmitWork` và gửi giao dịch on-chain trong Wave 7 trước khi thực hiện release ở Wave 8.
6. **Thời hạn bằng chứng đối tụng (`DEADLINE_PASSED: Đã hết thời hạn bằng chứng`):**
   - *Nguyên nhân:* Lệnh `evm_increaseTime` tua thời gian trên Hardhat vượt qua cửa sổ 72h nộp bằng chứng của developer.
   - *Cách xử lý:* Tận dụng cơ chế trọng tài: khi hết hạn 72h mà developer không nộp counter-evidence, Trọng tài có quyền trực tiếp ra phán quyết (`draftRuling`), phù hợp đúng luật nghiệp vụ tranh chấp.

## 5. Lệnh để chạy lại hoặc nạp thêm dữ liệu

```bash
# 1. Cấu hình môi trường
export BASE_URL=http://localhost:4001
export CHAIN_ID=31337

# 2. Sinh và nạp tiền cho ví demo (nếu chạy lại từ đầu)
bun run scripts/demo/wallets.ts
bun run scripts/demo/fund.ts

# 3. Chạy từng wave theo thứ tự (hỗ trợ cờ --dry-run)
bun run scripts/demo/populate.ts --wave W1    # Tạo 40 profiles & avatars
bun run scripts/demo/populate.ts --wave W2    # Tạo 150 bài toán
bun run scripts/demo/populate.ts --wave W3    # Tạo 500 comments & replies
bun run scripts/demo/populate.ts --wave W4    # Tạo 350+ ứng tuyển
bun run scripts/demo/populate.ts --wave W5    # Đặt trước & nạp tiền ký quỹ on-chain
bun run scripts/demo/populate.ts --wave W6    # Realtime task chat qua socket
bun run scripts/demo/populate.ts --wave W7    # Nộp bài on-chain & yêu cầu sửa
bun run scripts/demo/populate.ts --wave W8    # Release, Settlement, Dispute rulings
bun run scripts/demo/populate.ts --wave W9    # Đánh giá 2 chiều & kiểm duyệt spam

# 4. Kiểm tra đối soát dữ liệu
bun run scripts/demo/verify.ts
```
