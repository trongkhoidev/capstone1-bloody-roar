# Kế hoạch tối ưu tốc độ chuyển trang và API (2026-11-23)

## 1. Đã làm và số đo thật

Đo trên máy dev, dev server (`bun run dev`, Next 14.2.35 + webpack), DB là Supabase Seoul (RTT ~88 ms/query).

| Hạng mục | Trước | Sau | Cách đo |
|---|---|---|---|
| `app/layout.js` (chunk client có ở mọi trang) | 19 295 655 B | 3 782 219 B (-80%) | `curl` chunk từ dev server |
| SQL của `issues(first: 12)` khi có `applicationCount`/`commentCount` | 11 | 6 | Đếm `prisma:query` với `DEBUG_PRISMA=1` |
| SQL của `ISSUE_QUERY` (trang chi tiết) | 13 | 9 | như trên |
| `MarketplaceIssues` trên server đang chạy | 0,90 / 1,61 / 1,11 s | 1,13 / 0,91 / 0,52 / 0,45 s | 3-4 lần `curl` liên tiếp |

Thay đổi:
- `lib/auth/siwe.ts` không còn import `@thirdweb-dev/auth` / `@thirdweb-dev/wallets`; `issueAuthToken` chuyển sang `lib/auth.ts` (server). Store auth phía client kéo `siwe.ts` vào mọi trang nên toàn bộ SDK thirdweb v4 đi theo.
- `ISSUE_INCLUDE._count` thêm `comments`; bỏ `select` ở `applicationCount`, `commentCount`. Field-level `select` làm Pothos tải lại cả danh sách issue.

Chưa cải thiện được:
- **Thời gian compile từng trang ở dev vẫn 8–23 s** (mỗi trang ~7 800–10 000 module). Đây vẫn là nguyên nhân chính của cảm giác "đơ" khi mở trang lần đầu. Chunk nhỏ đi nhưng số module webpack phải xử lý chưa giảm nhiều.
- Chưa đo production build.

## 2. Việc cần làm ngay trước khi restart server

1. `.env` gốc đang trỏ `DATABASE_URL` tới Supabase. Muốn dùng DB local:
   - bật dòng `localhost:5433/bloody_roar_dev`, tắt dòng Supabase (cả `DIRECT_URL`).
   - `bun run db:migrate` (DB local đang ở schema cũ, chưa có bảng mới).
2. `ESCROW_ADDRESS` trong `.env` **không khớp** manifest chain local hiện tại. Server cổng 4000 chạy được chỉ vì bật từ trước khi manifest đổi; restart sẽ dừng với `FATAL: ESCROW_ADDRESS does not match the local deployment manifest`. Deploy lại contract (`bun run contracts:deploy`) hoặc cập nhật `ESCROW_ADDRESS` theo manifest.

Đã làm:
- `serverComponentsExternalPackages` thêm `@thirdweb-dev/auth`, `@thirdweb-dev/wallets`, `@thirdweb-dev/sdk`, `ethers`: phía server của mọi trang không còn bundle SDK thirdweb v4 (đến từ `getServerUser` ở root layout).
- `dashboard-view.tsx`, `issue-detail-view.tsx`: `sendPreparedCalls`, `signFundingIntent` nạp bằng `import()` khi bấm thao tác on-chain.
- `chat-room.tsx`, `create-issue-form.tsx`: import `@bloody-roar/shared/constants` và `/types` thay vì barrel `@bloody-roar/shared` (barrel re-export `viem`).

Bỏ / hoãn:
- 1.1 `onDemandEntries`: đo thấy trang không bị dispose sau 75 s nhàn rỗi (mở lại 0,01–0,16 s), không cần.
- 1.2 Turbopack (`TURBOPACK=1` với custom server): nhanh hơn khi mở lại trang nhưng `/api/graphql` trả 500 sau khi compile lại, `PothosSchemaError: Received undefined as a type ref` (thứ tự nạp module vòng trong `graphql/modules` khác webpack). Muốn dùng phải gỡ vòng import trước.
- 2.2 prefetch: `Link` ở Navbar dùng mặc định, production tự prefetch; không cần sửa.

## 5. Giai đoạn 3: API và payload

Số đo hiện tại (Supabase, sau phần đã sửa):

| Operation | SQL | Thời gian | Payload | Việc cần làm |
|---|---|---|---|---|
| `HomeBanner` | 3 danh sách, 90 issue | 1,0–1,8 s | 74 KB, không gzip | Bỏ `description` khỏi `NODE` hoặc chỉ lấy cho issue đang hiện; giảm `recent` từ 50 xuống 20; kiểm tra gzip ở reverse proxy production |
| `Inbox` (`myConversations`) | 12 | ~1,8 s | 470 B | Include issue đầy đủ chỉ để lấy `title`. Thêm field `issueTitle` vào `Conversation`, include `issue: { select: { title, clientId, developerId, status, … } }` đúng các field `chat-access` dùng; client đổi `issue { title }` → `issueTitle` |
| `Dashboard` | 14 | 0,5–1,0 s | 2,9 KB | 4 query riêng vào `escrow_projections` cùng điều kiện `developer ILIKE` → gộp 1 `groupBy` theo `phase`; chạy các nhánh độc lập bằng `Promise.all` |
| `GlobalSearch` | 9 | ~1,0 s | 2,8 KB | Kiểm tra debounce phía client (≥ 250 ms); trả issue không kèm include đầy đủ |
| `AdminStats` | 12 | ~0,6 s | 118 B | Gộp các `count` thành 1 `$queryRaw` hoặc `Promise.all` |
| `MarketplaceStats` | 4 | 0,35–0,47 s | 190 B | Chấp nhận được; có thể cache 30 s trong process |

Cột địa chỉ ví đang so bằng `ILIKE` (`escrow_projections.developer`, `claimable_balances.address`) nên không dùng được index btree. Lưu địa chỉ dạng lowercase và so bằng `=`; cần migration chuẩn hoá dữ liệu cũ.
